## xrGame 引擎核心面审查结论

**线程模型（已验证）**：主线程帧序 = seqParallelBeforRender（销毁队列）→ FrameMove（UpdateInit/UpdateRT + 脚本协程）→ 启动 GameThread 工作线程 → 主线程渲染 → wait。GameThread 并行跑 OnFrameMT、SoundEvent_Dispatch、UpdateDeferred/UpdateFinalize、seqParallel、LuaGC、seqFrameMT（device.cpp:387-406/498/528/549；EngineThreading.cpp:126-188；GamePersistent.cpp:794-809）。

**发现（按严重度）**

1. [高] EngineThreading.cpp:157-163 — 原主线程串行执行的 Device.seqParallel 整体搬到 GameThread，与主线程渲染（device.cpp:528）并发 — 回调含 ALife 更新（alife_update_manager.cpp:127-133, mtALife）、子弹（Level_Bullet_Manager.cpp:1319-1321）、MapManager（Level.cpp:1051-1052）、寻路构建（level_path_builder.h:81、detail_path_builder.h:42）、怪物声音（CustomMonster.cpp:458-459）— 这些回调写对象/寻路/墙标记状态，与渲染读路径并发，原语义为主线程渲染前串行 — 修复：触碰渲染数据的回调改走主线程 seqParallelBeforRender 段或按回调加同步。

2. [高] xrSheduler.cpp:239-247（Unregister 自旋段）— Unregister 先自旋等 m_current_step_obj 释放；若对象在 GameThread 自己的 shedule_Update 内调 Unregister(this)（自注销），同线程自旋永不退出→GameThread 挂死、主线程 wait() 冻结 — internal_Unregister 本有 m_current_step_obj==O 的自注销保护（xrSheduler.cpp:130-133），但自旋在其之前；m_current_step_obj 仅 volatile 非原子（xrSheduler.h:31）。触发者未证实（待确认），死锁结构确凿 — 修复：自旋前先判 m_processing_now 且同线程时直接走内部注销。

3. [中] HUDManager.cpp:160-161 + GameTask.cpp:185-195 — mt_TaskManager 时 UpdateTasks 在 GameThread 执行 lua functor（GameTask.cpp:191 `(*it)(...)`），SetTaskState→ChangeStateCallback 同样在 GameThread 触发 Actor()->callback（GameTask.cpp:135-137）— 与主线程 Level.cpp:1056 的同函数形成双路径；cvar（console_commands.cpp:3290）帧中途切换会同帧双跑/漏跑任务；脚本回调从渲染窗口线程进入，脚本若触碰 UI/对象表即竞态 — 修复：cvar 切换延迟到帧边界生效，脚本侧文档化线程约束。

4. [中] HUDManager.cpp:297,300 — mt_ui 下 UI().RenderFont() 与 m_pHUDTarget->Render() 在 ui_lock 之外，而 pUIGame->OnFrame()（168-170）与 pUIGame->Render()（293-294）已持锁 — 字体文本/地图标注可在 GameThread OnFrame 被并发修改，主线程绘制撕裂或崩溃 — 修复：RenderFont 纳入 ui_lock 或快照文本。

5. [中] EngineThreading.cpp:146-149 — mt_SchedulerRT 开启时整调度器（含 UpdateRT）移到 GameThread，RT 对象 shedule_Update 与主线程 FrameMove 的 UpdateCL 并发；防重入仅靠 DEBUG 断言（xrSheduler.cpp:~467 dbg_startframe）— 默认关闭，风险为选配 — 修复：RT 移线程前审计 RT 对象写集。

6. [中] Level_network.cpp:343-351 + Level_network_start_client.cpp:161-165 — mtNetwork（注释称 release 默认启用）时 net_Update（含 Server->Update）在 GameThread 经 seqFrameMT 执行，服务器侧实体/ALife 状态变更与主线程 FrameMove 中脚本对 alife()/server 的读取并发 — 具体竞态字段待确认 — 修复：Server 状态访问加锁或将 Server->Update 回主线程。

7. [低] xrSheduler.cpp:222-235/237-262 — Registration 队列无锁（Register/Unregister 直接 push_back，internal_Registration ~60-79 遍历+clear，分属主线程 UpdateInit 与 GameThread UpdateFinalize）— 当前仅靠“FrameMove 与渲染窗口不相交”的帧相位隐式错开，脆弱 — 修复：Registration 增设与 ItemsLock 同级的保护。

8. [低] Weapon.cpp:1213-1216 — 消音器过热 temperature 在 shedule_Update（GameThread）衰减，与主线程渲染读 glow/材质参数（Weapon.cpp:900-908 MarkAsGlowing）并发的 float/布尔竞态，影响有限 — 修复：渲染读取处快照或原子化。

## 发现列表

1. **[高] r4_rendertarget.cpp:500-516、525-529、148-153 — 同帧 PiP+DLSS 下主场景 viewport 被 SetActive 覆盖为显示尺寸** — 证据：ctor（525-529）Width/Height=Device.dw*（显示尺寸）；SetActive 经 set_viewport_size（148-153）直接 RSSetViewports(Width,Height)；而场景 RT 按 `dlss::RenderWidth()` 创建（707-708）=渲染尺寸；r4_R_render.cpp:347-356 每 view 调 `passTarget->SetActive()`，覆盖掉 dlss::BeginScene 设定的 render-size viewport（phase_PP.cpp:172-174 注释反证原意）。触发条件 r__svp_same_frame=1 且 render<display → 主场景以显示 viewport 光栅化进 render-size RT，边缘裁切。运行时视觉待确认。**修复**：SetActive 的 main 分支改按 dlss::RenderWidth/Height() 设 viewport。

2. **[中] r4_R_render.cpp:463-470 — 3DSS CopyResource 源/目标尺寸可能不匹配** — 镜内 pass 用 rt_tempzb（SVP 集，lens extent 尺寸）对 u_SceneDepth()（DLSS render-size sceneDepth），尺寸不等时 CopyResource 返回 E_INVALIDARG、拷贝静默丢弃。rt_tempzb 创建尺寸待确认。**修复**：拷贝前校验 Desc 或改 CopySubresourceRegion。

3. **[中] DlssIntegration.cpp:58-66 — StableOverlaysActive 一刀切清历史** — IsSVPActive/hud_params 期间每帧 ResetHistory 且 jitter=0：开镜瞬间 DLSS/FSR3 历史清零，退化为纯空间上采样。同帧 PiP 实现后该守卫可能已过时（待确认）。**修复**：仅屏蔽覆盖层区域累积，勿整帧清史。

4. **[中] WallmarksEngine.cpp:487、334-348 — wallmark 渲染全程持 xrCriticalSection** — Render() 用 `xrCriticalSectionGuard g(lock)` 包住整段流式绘制（BeginStream/FlushStream/set_Shader），物理线程 AddWallmark_internal（334）/AddSkeletonWallmark（346）需等整帧绘制完，wallmark 密集时物理线程阻塞尖峰。正确性成立、粒度过粗。**修复**：渲染侧先拷贝快照、释放锁后再绘制。

5. **[低] Blender_Recorder_StandartBinding.cpp:102-107、145-151 — jitter 绑定不区分 pass** — BeginScene（249-262）锁存 mainView 后 `dlss::Active()` 恒真，镜内 pass 也施加主视角 jitter（除以 RenderScreenWidth()=镜内 extent），产生亚像素偏移；镜内写入的 jitter 深度随后被主 pass 覆盖，影响小。**修复**：绑定条件加 `!SvpPassBound()`。

6. **[低] ResourceManager.cpp:590-655 — EvictStalledTextures 整批扫描持 creationGuard** — 循环内 `tex->Unload()`（释放 D3D surface）也在锁内，batch_size 上限 1000，放大与资源创建线程的锁竞争；默认关闭，影响受限。游标续扫、$user$/UI/refs 守卫本身闭环完整。**修复**：锁内仅收集候选，锁外 Unload。

7. **[低] phase_combine.cpp:334 — surface_get 引用疑似泄漏**（疑似移植前旧代码，待确认）。**修复**：核对生命周期后补释放或改 ref_ 包装。
